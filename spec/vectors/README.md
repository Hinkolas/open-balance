# Test vectors

The cross-platform contract. Every client implementation (Swift now, Kotlin
and C# later) and the Go reference MUST pass all of them. Change a vector
together with `docs/PROTOCOL.md`, then the implementations.

| File | Covers |
|---|---|
| `distribute.json` | §9.1 largest remainder, including products beyond 64 bits |
| `balances.json` | §9.2–9.5 validated payments → balances, pending amounts, transfers, expected balances and transfers, what can be paid now |
| `transfers.json` | §9.3 balances → who pays whom |
| `crypto.json` | §3, §5.1, §6 key derivation, envelope, signatures, chain (phase 1, generated by `go run ./cmd/server vectors`) |
| `ledger.json` | §7–8 signed event sequences → state and rejection reasons (phase 1, generated) |

Member ids in the math vectors are short opaque strings; they sort by bytes
exactly like the lowercase UUID strings used in real ledgers. In
`balances.json`, payments are already valid; `deleted` marks a deleted payment
and `arrivals` are the payment's recorded arrivals.
